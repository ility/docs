## Sign in with Ility

Clients that support MCP sign-in only need the server URL. When you connect, the client opens an Ility sign-in page. Sign in, then choose which workspace to allow and approve the request.

<Tabs>
  <Tab title="Claude">
    Ility is listed in the [Claude connectors directory](https://claude.ai/directory/ility), so you don't need to enter a URL. In Claude on the web or desktop:

    1. Open the [Ility listing](https://claude.ai/directory/ility). You can also find it in **Customize → Connectors**: choose **+** next to **Connectors** and search for ility.
    2. Connect it, then sign in to Ility and choose your workspace.

    On Team and Enterprise plans, an owner adds Ility for the organization first, in **Organization settings → Connectors**. Then each person connects and signs in with their own Ility account. If you can't add connectors, choose **Request** on the Ility listing to ask your owner.

    <Accordion title="Add Ility as a custom connector instead">
      If the directory isn't available to you, add the server by URL:

      1. Open **Customize → Connectors**, choose **Add**, then **Custom**, then **Web**.
      2. Name it `ility` and enter the URL `https://app.ilitylabs.com/mcp`.
      3. Connect it, then sign in and choose your workspace.
    </Accordion>
  </Tab>
  <Tab title="Claude Code">
    Add the server:

    ```bash
    claude mcp add --transport http ility https://app.ilitylabs.com/mcp
    ```

    Then run `/mcp` in Claude Code, choose **ility**, then choose **Authenticate** to sign in.
  </Tab>
  <Tab title="Cursor">
    Add the server to `~/.cursor/mcp.json`, or to `.cursor/mcp.json` in a project:

    ```json
    {
      "mcpServers": {
        "ility": {
          "url": "https://app.ilitylabs.com/mcp"
        }
      }
    }
    ```

    Cursor asks you to sign in the first time it uses the server.
  </Tab>
</Tabs>

<Note>
  A sign-in reaches every workspace you belong to. The workspace you pick when you sign in is the default. The assistant can work in your other workspaces by name, as described in [Choosing a workspace](/mcp/tools#choosing-a-workspace).
</Note>

If the client reports that it needs to reconnect, sign in again and make sure you pick a workspace on the approval screen.

## Check the connection

Ask the assistant "List my Ility sites." It should return each site with its slug, open issue count, and latest scan. If the Ility tools don't show up, turn the connector on for the chat, or see [Troubleshooting](/mcp/workflows#troubleshooting).

## Use an API key

For clients without MCP sign-in, [create an API key](/api/api-keys) and send it in the `Authorization` header. Most clients take a configuration like this:

```json
{
  "mcpServers": {
    "ility": {
      "type": "http",
      "url": "https://app.ilitylabs.com/mcp",
      "headers": {
        "Authorization": "Bearer ilk_..."
      }
    }
  }
}
```

The **API keys** settings tab has this configuration ready to copy. A key only works in its own workspace.

## Disconnect

To disconnect a client that signed in, remove the connector or server from the client. To cut off a client that uses a key, revoke the key in **Settings → API keys**.
